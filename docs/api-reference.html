Response shape

Every response takes one of three forms. Build against these — no endpoint departs from them.

Single resource

// 200
{ "data": { … } }

Paginated list

// 200
{
  "data": [ … ],
  "meta": {
    "current_page": 1,
    "per_page": 20,
    "total": 137,
    "last_page": 7
  }
}

Error

// 422
{
  "message": "Invalid verification code",
  "errors": {
    "otp": ["Invalid verification code"]
  }
}

Page size caps at 100. A larger per_page is silently clamped to 100 — no error is returned.

Status codes

Used with the same meaning across every endpoint.

200Success.
201Resource created — returned in the response body.
401Token missing or revoked. Send the user back to login.
404Not found — or it exists but belongs to someone else. The two are deliberately indistinguishable, so the API never confirms another owner's property exists.
422Invalid input — read errors to bind each message to its field.
429Rate limited (5 OTP requests per hour, per phone).
500Unexpected failure. The message is always generic — details are logged server-side and never reach the app.

Authentication

Phone number plus a one-time code. The code is currently fixed for testing; wiring up a real SMS provider will not change the request or response shape.

POST /auth/request-otp No token

Sends a verification code to a registered phone number.

Request

Field Type Notes
phonereq string Accepts 05…, +9665…, 9665… 
{ "phone": "0511111111" }

Response

200 
{
  "data": {
    "message": "Verification code sent",
    "expires_in": 300
  }
}
404 Unregistered number 
{ "message": "Phone number is not registered" }

Rate limit: 5 requests per hour per phone + IP. Exceeding it returns 429. The counter increments even for unregistered numbers.

POST /auth/verify-otp No token

Exchanges a valid code for the token sent with every subsequent request.

Request

Field Type Notes
phonereq string Same number as the request step
otpreq string 4–6 digits · testing code is 6666 
{
  "phone": "0511111111",
  "otp": "6666"
}

Response

200 
{
  "data": {
    "token": "17|xxxxxxxxxxxxxxxx",
    "owner": {
      "id": 33,
      "name": "محمد عبدالله الحقباني",
      "national_id": "1006272601",
      "phone": "0511111111",
      "email": null
    }
  }
}
422 Wrong or expired code 
{
  "message": "Invalid verification code",
  "errors": { "otp": ["Invalid verification code"] }
}

Single use. The code is consumed on successful verification and expires after 5 minutes. Store the token securely and send it in the Authorization header.

POST /auth/logout 🔒 Token required

Revokes only this device's token — other devices stay signed in.

Response

200 
{ "data": { "message": "Signed out" } }

Param Type Notes

Response

200 
{
  "data": [
    {
      "type": "parcel",
      "id": 34,

Searching by owner name does not reveal other owners. Even with type=owner, results stay scoped to the token holder's parcels. Capped at 50 results.

Modification requests

Parcel data is synced from the source of record and cannot be edited directly — the owner submits a request, and the team reviews it.

Allowed values

Sent and received in Arabic exactly as shown — that is how they are stored in the database. Translating them for display is the app's responsibility.

asset_type

أرض land شقة apartment عمارة building فيلا villa مستودع warehouse

land_transaction

مباعة sold مؤجرة leased قيد البيع for sale خاصة private

deed_status

محدث current قديم superseded

deed_class

زراعي agricultural سكني residential صناعي industrial

qrar_source

بلدي municipal مكتب هندسي eng. office بدون none

allocation_method

محدد بدقة precise محدد حسب الموقع العام approximate لم يتم تحديد الموقع unlocated

fall_in

مخطط زراعي agri. plan مخطط بلدية municipal plan

document.type

صك deed كروكي مساحي survey sketch جوية aerial أرضية ground

Messages follow the header; values do not. Send Accept-Language: ar or messages come back in English. The enum values themselves stay Arabic in every case — they are data, not UI copy.
